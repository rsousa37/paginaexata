1. INTRODUÇÃO E CONCEITOS ESPECÍFICOS DO EXT4

Ao gerenciar unidades de armazenamento em ambientes Linux voltados para desenvolvimento ou backup, o sistema de arquivos adotado por padrão na maioria das distribuições modernas é o EXT4. Diferente de sistemas como o NTFS, o EXT4 impõe um controle rígido de segurança baseado em propriedades e permissões nativas do núcleo do sistema.

1.1 O Diretório lost+found

Ao formatar uma partição em EXT4, o sistema cria automaticamente no diretório raiz da unidade uma pasta chamada lost+found.

  • Função Prática: Serve como um depósito de segurança para a ferramenta de checagem do sistema de arquivos (fsck). Se o computador sofrer um desligamento abrupto, o fsck analisa o disco no próximo boot e fragmentos de dados órfãos são movidos para cá.
  • Manutenção: Esta pasta não deve ser deletada. Em um sistema operacional saudável, ela permanece completamente vazia.

2. GERENCIAMENTO DE PERMISSÕES E PROPRIEDADES VIA TERMINAL

Para que qualquer aplicativo de automação funcione gravando dados em discos secundários, o usuário operacional precisa deter a propriedade do ponto de montagem.

2.1 Alteração de Proprietário (chown)

O utilitário chown (Change Owner) define qual conta de usuário e qual grupo gerenciam um diretório.

sudo chown -R $USER:$USER /caminho/do/diretorio
  • sudo: Executa a ação com privilégios de superusuário.
  • -R: Aplica a alteração de forma recursiva (afeta a pasta, subpastas e todos os arquivos existentes).
  • $USER:$USER: Variável que puxa automaticamente o nome do usuário atual e o seu grupo padrão.

2.2 Alteração de Modos de Acesso (chmod)

sudo chmod -R 755 /caminho/do/diretorio

A notação octal 755 segmenta os privilégios em três níveis essenciais:

  1. 7 (Dono): Permissão total. Soma de 4 (leitura) + 2 (escrita) + 1 (execução).
  2. 5 (Grupo): Permissão de leitura e execução (4 + 1).
  3. 5 (Outros): Permissão de leitura e execução (4 + 1).

3. FLUXO DE OPERAÇÃO DO DÉJÀ DUP (DUPLICITY)

3.1 Backups Completos (Full) vs. Incrementais (Inc)

  • Backup Full (duplicity-full): Uma cópia integral de todas as pastas selecionadas. É gerado na primeira execução ou quando há mudanças drásticas no ponto de montagem.
  • Backup Incremental (duplicity-inc): Armazena exclusivamente os arquivos que sofreram modificações desde o último backup.

APÊNDICE: ANÁLISE DE FALHAS E SOLUÇÕES APLICADAS

FALHA 01: Permissão Negada no Destino Inicial (Dados_Backup)

Sintoma: O aplicativo Déjà Dup indicava falha catastrófica ao tentar gravar os primeiros volumes do tipo duplicity-full.

Causa Raiz: A raiz de partições novas pertencem ao usuário administrativo root por padrão.

sudo chown -R $USER:$USER /media/robson/Dados_Backup
sudo chmod -R 755 /media/robson/Dados_Backup

FALHA 02: Exposição Indesejada da Pasta lost+found

Sintoma: O diretório exibia acesso livre e visibilidade completa com o usuário padrão.

Causa Raiz: A aplicação do comando recursivo (-R) na raiz afetou estruturas nativas do sistema.

sudo chown root:root /media/robson/Extra_Lab/lost+found

FALHA 03: Erro de Timeout e Permissão Negada em Novo Ponto de Montagem

"Giving up after 5 attempts. Error: Error opening file... Permission denied"

Causa Raiz: O ponto de montagem mudou para a raiz de mídias (/media/backup/), redefinindo o dono para root.

sudo chown -R $USER:$USER /media/backup
sudo chmod -R 755 /media/backup
